## 이슈 유형 (Issue Types)

Jira에서 모든 작업 단위는 **이슈(Issue)**라고 부릅니다. 이슈는 목적과 크기에 따라 여러 유형으로 나뉩니다.

### Epic (에픽)

```
🏔️ Epic = 큰 기능 덩어리, 여러 스프린트에 걸쳐 완성
```

- **정의**: 하나의 큰 목표나 기능을 나타내는 최상위 작업 단위
- **기간**: 보통 1~3개월, 여러 스프린트에 걸쳐 진행
- **예시**:
  - "사용자 인증 시스템 구축"
  - "결제 모듈 개발"
  - "대시보드 리뉴얼"
- **포함 관계**: 여러 Story, Task를 포함

### Story (스토리 / 사용자 스토리)

```
📖 Story = 사용자 관점의 기능 요구사항
```

- **정의**: 최종 사용자에게 가치를 제공하는 기능 단위
- **작성 형식**: "~로서, ~을 원한다, ~하기 위해" (As a... I want... So that...)
- **기간**: 보통 1개 스프린트 내 완료 가능한 크기
- **예시**:
  - "사용자로서, 소셜 로그인을 원한다, 빠르게 가입하기 위해"
  - "관리자로서, 사용자 목록을 필터링하고 싶다, 특정 사용자를 찾기 위해"

### Task (태스크 / 작업)

```
✅ Task = 구체적인 기술적 작업
```

- **정의**: 개발 과정에서 필요한 구체적인 작업 항목
- **특징**: 사용자 가치보다는 기술적 필요에 의한 작업
- **기간**: 보통 몇 시간 ~ 2일 이내
- **예시**:
  - "데이터베이스 스키마 설계"
  - "CI/CD 파이프라인 구축"
  - "API 문서 작성"
  - "코드 리팩토링"

### Bug (버그)

```
🐛 Bug = 기대와 다르게 동작하는 문제
```

- **정의**: 소프트웨어가 의도한 대로 작동하지 않는 결함
- **포함 정보**: 재현 단계, 기대 결과, 실제 결과, 환경 정보
- **예시**:
  - "로그인 버튼 클릭 시 페이지 새로고침됨"
  - "모바일에서 메뉴가 표시되지 않음"

### Sub-task (하위 작업)

```
📎 Sub-task = 상위 이슈를 더 작은 단위로 분할
```

- **정의**: Story나 Task를 더 작은 단위로 나눈 작업
- **특징**: 독립적으로 존재할 수 없고, 반드시 상위 이슈에 속함
- **용도**: 큰 작업을 여러 사람이 나눠서 할 때, 진행 상황 세분화
- **예시** (상위: "소셜 로그인 구현"):
  - "Google OAuth 연동"
  - "Kakao OAuth 연동"
  - "로그인 UI 구현"

## 이슈 계층 구조

```
┌─────────────────────────────────────────────────────────┐
│                     🏔️ EPIC                             │
│              "사용자 인증 시스템 구축"                    │
│                   (1~3개월)                             │
└─────────────────────────────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │ 📖 Story │    │ 📖 Story │    │ ✅ Task  │
    │소셜로그인│    │비밀번호찾기│    │DB 스키마│
    │ (1주)    │    │  (3일)   │    │  (2일)  │
    └──────────┘    └──────────┘    └──────────┘
          │
    ┌─────┼─────┐
    ▼     ▼     ▼
┌──────┐┌──────┐┌──────┐
│Sub   ││Sub   ││Sub   │
│task  ││task  ││task  │
│Google││Kakao ││UI    │
└──────┘└──────┘└──────┘
```

### 관계 정리

| 구분 | 크기 | 기간 | 포함 | 독립성 |
|------|------|------|------|--------|
| Epic | 대 | 1~3개월 | Story, Task | 독립 |
| Story | 중 | 1 스프린트 | Sub-task | 독립 |
| Task | 중 | 수시간~2일 | Sub-task | 독립 |
| Bug | 소~중 | 수시간~수일 | Sub-task | 독립 |
| Sub-task | 소 | 수시간 | 없음 | 종속 |

## 백로그와 스프린트

### Backlog (백로그)

```
📋 Backlog = 해야 할 모든 작업이 쌓여있는 대기열
```

- **정의**: 아직 스프린트에 포함되지 않은 모든 이슈의 목록
- **특징**:
  - 우선순위에 따라 정렬됨 (위가 높은 우선순위)
  - 언제든 이슈 추가/수정/삭제 가능
  - PO(Product Owner)가 관리하고 우선순위 결정
- **종류**:
  - **Product Backlog**: 제품 전체의 할 일 목록
  - **Sprint Backlog**: 특정 스프린트에서 할 일 목록

### Sprint (스프린트)

```
🏃 Sprint = 고정된 기간 동안의 개발 주기
```

- **정의**: 보통 1~4주(대부분 2주)의 고정된 개발 기간
- **특징**:
  - 시작과 끝이 명확함
  - 스프린트 시작 후에는 범위 변경 최소화
  - 스프린트 끝에 동작하는 결과물 산출

### 백로그 → 스프린트 흐름

```
┌─────────────────────┐      ┌─────────────────────┐
│   Product Backlog   │      │   Sprint Backlog    │
│   (제품 백로그)      │      │   (스프린트 백로그)  │
├─────────────────────┤      ├─────────────────────┤
│ □ 기능 A (High)     │─────▶│ □ 기능 A            │
│ □ 기능 B (High)     │─────▶│ □ 기능 B            │
│ □ 기능 C (Medium)   │─────▶│ □ 버그 X 수정       │
│ □ 기능 D (Medium)   │      └─────────────────────┘
│ □ 기능 E (Low)      │              │
│ □ 버그 X 수정       │──────────────┘
│ □ 기능 F (Low)      │        Sprint
│ □ ...               │       Planning
└─────────────────────┘       (계획 회의)
        ▲
        │ 새로운 요구사항,
        │ 버그, 아이디어
        └────────────────
```

### 스프린트 사이클

```
┌──────────────────────────────────────────────────────────────┐
│                      스프린트 (2주)                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Day 1              Week 1-2                    Last Day     │
│    │                   │                           │         │
│    ▼                   ▼                           ▼         │
│ ┌──────┐          ┌──────┐                    ┌──────────┐   │
│ │Sprint│          │Daily │ ← 매일 15분        │Sprint    │   │
│ │Plan  │          │Scrum │   진행상황 공유    │Review    │   │
│ │계획  │          │스탠드업│                   │리뷰/회고  │   │
│ └──────┘          └──────┘                    └──────────┘   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
                     다음 스프린트 시작
```

## 보드 (Board)

보드는 이슈의 진행 상태를 시각적으로 보여주는 도구입니다.

### Scrum Board vs Kanban Board

| 특징 | Scrum Board | Kanban Board |
|------|-------------|--------------|
| 스프린트 | 있음 (고정 주기) | 없음 (연속 흐름) |
| 작업 투입 | 스프린트 시작 시 | 언제든지 |
| WIP 제한 | 선택적 | 핵심 (컬럼별 제한) |
| 적합한 경우 | 정기 배포, 팀 개발 | 운영/유지보수, 지원 |
| 측정 지표 | Velocity, Burndown | Cycle Time, Throughput |

### 보드 예시 (Kanban)

```
┌─────────────┬─────────────┬─────────────┬─────────────┐
│   To Do     │ In Progress │  In Review  │    Done     │
│   (대기)    │   (진행중)   │  (리뷰중)   │   (완료)    │
├─────────────┼─────────────┼─────────────┼─────────────┤
│ ┌─────────┐ │ ┌─────────┐ │ ┌─────────┐ │ ┌─────────┐ │
│ │OAR-10   │ │ │OAR-8    │ │ │OAR-5    │ │ │OAR-1    │ │
│ │로그인 UI│ │ │API 연동 │ │ │DB 설계  │ │ │환경설정 │ │
│ └─────────┘ │ └─────────┘ │ └─────────┘ │ └─────────┘ │
│ ┌─────────┐ │ ┌─────────┐ │             │ ┌─────────┐ │
│ │OAR-11   │ │ │OAR-9    │ │             │ │OAR-2    │ │
│ │테스트   │ │ │버그수정 │ │             │ │문서작성 │ │
│ └─────────┘ │ └─────────┘ │             │ └─────────┘ │
└─────────────┴─────────────┴─────────────┴─────────────┘
```

## 워크플로우와 상태

### 기본 워크플로우

```
┌────────┐     ┌────────────┐     ┌────────────┐     ┌────────┐
│ To Do  │────▶│In Progress │────▶│ In Review  │────▶│  Done  │
│ (대기) │     │  (진행중)   │     │  (리뷰중)  │     │ (완료) │
└────────┘     └────────────┘     └────────────┘     └────────┘
    ▲                                    │
    │            되돌리기 가능            │
    └────────────────────────────────────┘
```

### 상태 카테고리

Jira는 모든 상태를 3개의 카테고리로 분류합니다:

| 카테고리 | 의미 | 예시 상태 |
|----------|------|-----------|
| **To Do** (해야 할 일) | 아직 시작 안 함 | 대기, 백로그, 아이디어 |
| **In Progress** (진행 중) | 작업 중 | 개발중, 리뷰중, 테스트중 |
| **Done** (완료) | 작업 완료 | 완료, 배포됨, 종료 |

### Transition (전환)

상태 간 이동을 **Transition**이라고 합니다.

```
"Start Progress" 버튼 클릭
        │
        ▼
To Do ─────────────────▶ In Progress
        (전환/Transition)
```

## 추정과 측정

### Story Points (스토리 포인트)

```
📊 Story Point = 작업의 상대적 크기/복잡도를 나타내는 숫자
```

- **정의**: 시간이 아닌, 상대적인 작업량을 표현
- **피보나치 수열 사용**: 1, 2, 3, 5, 8, 13, 21...
- **왜 시간이 아닌 포인트?**:
  - 사람마다 작업 속도가 다름
  - 상대적 비교가 더 정확함
  - 팀 전체의 예측이 가능해짐

**포인트 가이드 예시**:

| 포인트 | 복잡도 | 예시 |
|--------|--------|------|
| 1 | 매우 간단 | 오타 수정, 설정값 변경 |
| 2 | 간단 | 간단한 UI 수정, 로그 추가 |
| 3 | 보통 | 새 API 엔드포인트 추가 |
| 5 | 복잡 | 새 기능 개발 (중간 규모) |
| 8 | 매우 복잡 | 복잡한 비즈니스 로직 구현 |
| 13+ | 분할 필요 | 너무 큼, 더 작은 단위로 분할 |

### Velocity (벨로시티)

```
🚀 Velocity = 스프린트당 완료한 스토리 포인트 합계
```

- **용도**: 팀의 개발 속도 측정, 다음 스프린트 계획에 활용
- **예시**:
  - Sprint 1: 21 points 완료
  - Sprint 2: 18 points 완료
  - Sprint 3: 24 points 완료
  - 평균 Velocity: 21 points

## 기타 주요 개념

### Priority (우선순위)

| 우선순위 | 의미 | 대응 |
|----------|------|------|
| Highest | 시스템 장애, 서비스 불가 | 즉시 착수 |
| High | 주요 기능 장애 | 당일 착수 |
| Medium | 일반적인 기능 개선 | 계획에 따라 |
| Low | 사소한 개선 | 여유 시 |
| Lowest | Nice-to-have | 언젠가 |

### Label (라벨)

```
🏷️ Label = 이슈를 분류하는 태그
```

- **용도**: 이슈 필터링, 그룹화
- **예시**: `frontend`, `backend`, `urgent`, `documentation`, `refactoring`

### Component (컴포넌트)

```
🧩 Component = 프로젝트의 논리적 하위 영역
```

- **용도**: 프로젝트를 기능 영역별로 구분
- **예시**: `인증`, `결제`, `알림`, `관리자`, `API`

### Version / Fix Version (버전)

```
📦 Version = 배포 버전 (릴리즈)
```

- **용도**: 이슈가 어느 버전에 포함되는지 추적
- **예시**: `v1.0.0`, `v1.1.0-beta`, `2024-Q1`

### Assignee / Reporter

| 역할 | 의미 |
|------|------|
| **Assignee** (담당자) | 이슈를 실제로 수행하는 사람 |
| **Reporter** (보고자) | 이슈를 생성한 사람 |

## 실무 팁

### 좋은 이슈 제목 작성법

```
❌ 나쁜 예: "버그 수정", "기능 추가", "문제 해결"
✅ 좋은 예: "[로그인] 소셜 로그인 시 토큰 만료 처리 누락"
```

**패턴**: `[영역] 구체적인 작업 내용`

### 이슈 설명 필수 포함 사항

**Story의 경우**:
- 사용자 스토리 (As a... I want... So that...)
- 인수 조건 (Acceptance Criteria)
- 화면 설계 or 참고 자료

**Bug의 경우**:
```markdown
## 재현 단계
1. 로그인 페이지 접속
2. 이메일 입력 후 다음 버튼 클릭
3. ...

## 기대 결과
비밀번호 입력 화면으로 이동

## 실제 결과
페이지가 새로고침됨

## 환경
- 브라우저: Chrome 120
- OS: macOS 14.0
```

### 스프린트 운영 팁

1. **스프린트 목표 설정**: 단순 이슈 나열이 아닌, 달성할 목표 정의
2. **적정 용량 배정**: Velocity의 80% 정도만 계획
3. **버퍼 확보**: 긴급 이슈, 예상치 못한 문제 대비
4. **데일리 스크럼**: 15분 이내, 진행/계획/블로커 공유

### JQL 유용한 쿼리

```sql
-- 내가 담당한 진행 중인 이슈
assignee = currentUser() AND status = "In Progress"

-- 이번 스프린트의 미완료 이슈
sprint in openSprints() AND status != Done

-- 최근 7일간 생성된 버그
project = OAR AND issuetype = Bug AND created >= -7d

-- 우선순위 높은 미할당 이슈
priority in (Highest, High) AND assignee is EMPTY
```
