# Async 변환 작업 - Batch Embed & Backend API

> **Category**: batch, backend
> **Date**: 2026-01-15
> **Status**: completed

---

## Context (배경)

- 논문 수집 파이프라인의 I/O 바운드 작업들이 동기 방식으로 구현되어 성능 병목 발생
- 특히 Batch Embed Task에서 ThreadPoolExecutor + 동기 OpenAI API 조합이 비효율적
- `논문수집개선안.md` 문서에 분석 결과 및 구현 가이드 작성 완료

## Solution (해결 방안)

### Phase 1: Batch Embed (최우선)
- [x] `batch/src/embedding/embeddings.py` - AsyncEmbeddingClient 추가
- [x] `batch/src/tasks/embed.py` - ThreadPoolExecutor → asyncio.gather
- [x] `batch/src/embedding/__init__.py` - export 추가

### Phase 2: Backend API
- [x] `backend/app/services/embedding_service.py` - AsyncOpenAI
- [x] `backend/app/services/llm_service.py` - AsyncOpenAI
- [x] 호출부 변경 (rag_service.py, lab.py, ai.py, agent nodes)

### Phase 3: S3 서비스 (선택) - 미완료
- [ ] aioboto3 의존성 추가
- [ ] `backend/app/services/s3_service.py` - async 변환

## Changes (변경 사항)

### 생성된 파일
- `docs/history/batch-01-260115.md` - 본 히스토리 파일

### 수정된 파일

#### Phase 1: Batch
- `batch/src/embedding/embeddings.py`
  - `AsyncEmbeddingClient` 클래스 추가
  - `async def embed_text()`, `async def embed_texts()` 구현

- `batch/src/tasks/embed.py`
  - `process_single_paper_async()` 추가
  - `run_embed_coroutine()` async 함수 추가
  - `run_embed` Celery task에 `use_async` 파라미터 추가
  - `asyncio.gather` + `asyncio.Semaphore(10)` 패턴 적용

- `batch/src/embedding/__init__.py`
  - `AsyncEmbeddingClient` export 추가

#### Phase 2: Backend Services
- `backend/app/services/embedding_service.py`
  - `OpenAI` → `AsyncOpenAI` 변환
  - `embed_text()`, `embed_texts()` async 변환

- `backend/app/services/llm_service.py`
  - `OpenAI` → `AsyncOpenAI` 변환
  - `generate()` async 변환
  - `generate_stream()` → `AsyncGenerator` 변환

- `backend/app/services/rag_service.py`
  - `retrieve()` async 변환 (`await embedding_service.embed_text()`)

#### Phase 2: Backend Routers
- `backend/app/routers/lab.py`
  - `test_search()` → `async def test_search()`
  - `test_generate()` → `async def test_generate()`
  - `await embedding_service.embed_text()`, `await rag_service.retrieve()`
  - `async for chunk in llm_service.generate_stream()`

- `backend/app/routers/ai.py`
  - 스레드 기반 agent 실행 → async generator 직접 iteration
  - `queue.Queue` + `threading.Thread` 제거
  - `async for event in agent_service.execute_stream()` 패턴 적용

#### Phase 2: Agent System
- `backend/app/services/agent/service.py`
  - `execute()` → `async def execute()` (`.ainvoke()`)
  - `execute_stream()` → `AsyncGenerator` 반환 (`.astream()`)

- `backend/app/services/agent/nodes/executor.py`
  - `execute_tasks()` → `async def execute_tasks()`
  - `_execute_single_task()` → async
  - `_execute_rag_search()` → async (`await rag_service.retrieve()`)
  - `_execute_compare()` → async (`AsyncOpenAI`)
  - `execute_direct_rag()` → async
  - `asyncio.gather()` 병렬 실행 적용

- `backend/app/services/agent/nodes/synthesizer.py`
  - `synthesize_answer()` → `async def synthesize_answer()`
  - `synthesize_answer_stream()` → `AsyncGenerator`
  - `await llm_service.generate()`, `async for ... llm_service.generate_stream()`

## Notes

- 참고 문서: `논문수집개선안.md`
- 하위 호환성: Batch에서 기존 동기 `EmbeddingClient` 유지
- Rate Limit: `asyncio.Semaphore(10)`으로 동시성 제어
- LangGraph: `.invoke()` → `.ainvoke()`, `.stream()` → `.astream()`

### 예상 성능 개선
- Batch Embed: ~10x (ThreadPoolExecutor + GIL → asyncio.gather)
- Backend 동시 요청: ~5x (concurrent request handling)
