## Context (배경)

RAG(Retrieval-Augmented Generation) 품질을 테스트하고 개선하기 위한 "랩실" 기능이 필요하다.
현재 RAG 파이프라인이 구축되어 있지만, 품질을 체계적으로 측정하고 개선할 수 있는 도구가 없다.

### 현재 RAG 아키텍처 (backend/)
- `rag_service.py`: Parent Retrieval 패턴으로 검색
- `weaviate_service.py`: 벡터 DB 하이브리드 검색
- `embedding_service.py`: 텍스트 임베딩 생성
- `llm_service.py`: LLM 스트리밍 응답
- `AnswerLog`: 증거(references) + latency 저장

## 기술 설계

### 아키텍처

```
Admin Frontend → Admin Backend → User Backend (FastAPI)
    (Next.js)       (NestJS)            │
                                  RAG Service → Weaviate
                                  LLM Service → OpenAI
```

### Admin Backend (NestJS)

**환경변수**: `USER_BACKEND_URL=http://localhost:8000`

**API 엔드포인트**:
- `GET /lab/status` - User Backend 상태 확인
- `POST /lab/search` - 검색 테스트
- `POST /lab/generate` - 답변 생성 테스트
- `POST /lab/feedback` - 피드백 저장

### User Backend (FastAPI)

**API 엔드포인트**:
- `POST /lab/search` - RAG 검색 (하이브리드)
- `POST /lab/generate` - RAG + LLM 답변 생성

### Admin Frontend (Next.js)

**페이지**: `/lab`
- 검색 테스트 / 답변 생성 테스트 모드 전환
- 파라미터 조정 (limit, alpha)
- 결과 시각화 (청크, 참조 문헌)
- 피드백 버튼

## 에러 처리

### Weaviate 스키마 없음 (임베딩 데이터 없음)

**상황**: Weaviate에 `PaperChunk` 컬렉션이 없는 경우 (초기 상태, 또는 리셋 후)

**처리 방식**:
1. User Backend에서 `could not find class` 에러 감지
2. HTTP 503 응답 + `no_embedding_data` 에러 타입 반환
3. Admin Frontend에서 친화적인 메시지와 Papers 페이지 링크 표시

**참고**: "스키마 없음" ≠ "검색 결과 없음"
- 스키마 없음: 503 에러, 데이터 자체가 준비되지 않음
- 검색 결과 없음: 200 + 빈 배열, 정상 응답 (매치되는 문서 없음)
