# Admin Lab A/B 비교 UI 재설계

> **Category**: admin
> **Date**: 2026-01-07
> **Status**: completed

---

## Context (배경)

기존 Admin Lab의 A/B 비교 기능은 Reranker ON/OFF만 비교할 수 있었음. 사용자가 모든 검색 파라미터(limit, alpha, reranker)를 독립적으로 설정하여 비교할 수 있도록 UI 재설계 필요.

사용자 요구사항:
- 모든 파라미터를 자유롭게 조합하여 A/B 비교
- 두 설정의 결과를 나란히 보고 사용자가 직접 판단
- 자동화된 메트릭이 아닌 시각적 비교

## Solution (해결 방안)

- [x] 재사용 가능한 SearchConfigPanel 컴포넌트 생성
- [x] LabConfigForm에 A/B 독립 설정 패널 적용
- [x] Admin Backend DTO 및 서비스 수정 (configA/configB)
- [x] LabCompareResults 컴포넌트 재작성
- [x] 프론트엔드 API 타입 업데이트

## Architecture

### 새로운 타입 구조

```typescript
// 개별 검색 설정
interface SearchConfig {
  limit: number;
  alpha: number;
  reranker: string | null;  // null이면 리랭킹 안함
}

// A/B 비교 결과
interface CompareResults {
  configA?: SearchTestResult;
  configB?: SearchTestResult;
}
```

### API 변경

```typescript
// 기존: withReranker/withoutReranker
// 변경: configA/configB (독립적인 설정)

POST /lab/compare
{
  "query": "...",
  "configA": { "limit": 10, "alpha": 0.7, "reranker": "bge" },
  "configB": { "limit": 10, "alpha": 0.5, "reranker": null }
}
```

## Notes

- Chunker/Embedder 선택은 인덱싱 시점에 결정되므로, 검색 시점에는 Retriever(alpha), Reranker만 변경 가능
- 향후 다중 임베딩 모델 지원 시 확장 가능한 구조
