## Context (배경)

### 문제 상황
- 임베딩 시 Weaviate에서 중복 ID 에러: `id 'xxx' already exists`
- UUID는 `uuid5(NAMESPACE_DNS, chunk_id)`로 결정적 생성
- chunk_id = `{paper_id}|{section_name}|{chunk_index}`

### 근본 원인
`SECTION_NAME_MAP`에서 서로 다른 섹션을 같은 이름으로 정규화하여 chunk_id 충돌:
- `conclusion` → `discussion` (Discussion 섹션과 충돌)
- `background` → `introduction` (Introduction 섹션과 충돌)
- `summary` → `abstract` (Abstract 섹션과 충돌)

### 영향받은 논문: 37건
- 35건: discussion + conclusion 중복
- 1건: introduction + background 중복
- 1건: abstract + summary 중복

## 청킹 전략 (OAR-31/104 테스트 결과)

### 채택 전략: Parent-Child Retrieval (Strategy C)

OAR-31 스파이크에서 3가지 전략을 비교 테스트:

| 전략 | 설명 | 결과 |
|------|------|------|
| A | 대형 청크 (섹션 전체) | 검색 품질 낮음 |
| B | 섹션 보존 청킹 | 중간 |
| **C** | **작은 청크 검색 → 부모 섹션 전달** | **채택** |

### Strategy C 동작 방식
```
1. 검색 시: 작은 청크 (700토큰)로 세밀하게 검색
2. LLM 전달 시: 해당 청크의 부모 섹션 전체를 전달
3. 장점: 검색 정밀도 + 충분한 컨텍스트
```

### Adaptive Chunking 규칙
- **1000토큰 이하 섹션**: 청킹 없이 통째로 임베딩
- **1000토큰 초과 섹션**: 700토큰 청크로 분할
- 설정: `adaptive_threshold_tokens=1000`, `chunk_size_tokens=700`

### Parent Retrieval 방식
- Weaviate 기반: `paperId + section` 필터로 해당 섹션의 모든 청크 조회
- 조회된 청크들을 합쳐서 부모 섹션 재구성
