## Context (배경)

Study Plan Agent는 연구 가설을 기반으로 실험 계획서(Plan A, Plan B)를 자동 생성하는 AI 에이전트입니다.
- **v3**: 고정 워크플로우 (LangGraph) 기반
- **v4**: 자율 에이전트 (ReAct 패턴) 기반

이 문서는 v3부터 v4까지 발생한 주요 이슈와 해결 과정을 정리합니다.

### 이슈 1: Action Name 파싱 오류

**증상**:
```
Invalid action name: "design_experiment for question 1"
```

**원인**: LLM이 action 필드에 도구 이름 외에 설명을 추가

**해결**: `reasoner.py`에 `_sanitize_action_name()` 메서드 추가

```python
def _sanitize_action_name(self, action: str) -> str:
    """Extract valid tool name from potentially noisy action string."""
    valid_tools = self.tools.list_tools() + ["FINISH"]

    for tool in valid_tools:
        if action.lower().startswith(tool.lower()):
            return tool

    return "ask_user"  # fallback
```

**파일**: `backend/app/services/agent/study_plan/v4/core/reasoner.py:183-228`

### 이슈 2: JSON 파싱 오류

**증상**:
```
JSONDecodeError: Expecting property name enclosed in double quotes
```

**원인**: LLM이 trailing comma, single quotes 등 잘못된 JSON 생성

**해결**: `_fix_json_string()` 및 `_extract_action_from_text()` 추가

```python
def _fix_json_string(self, json_str: str) -> str:
    # Remove trailing commas
    json_str = re.sub(r',\s*([}\]])', r'\1', json_str)
    # Replace single quotes
    if '"' not in json_str and "'" in json_str:
        json_str = json_str.replace("'", '"')
    return json_str
```

**파일**: `backend/app/services/agent/study_plan/v4/core/reasoner.py:230-288`

### 이슈 3: 도구 파라미터 누락/불일치 (핵심 문제)

**증상**:
```

search_rag: RAGSearchTool.run() missing 1 required positional argument: 'query'
```

**원인**:
1. LLM에게 도구 파라미터 스키마가 충분히 전달되지 않음
2. `get_descriptions_for_llm()`이 텍스트 설명만 제공, 구조화된 스키마 없음
3. LLM이 파라미터를 "추측"해서 호출

**임시 해결** (Symptom Fix):
- `executor.py`에서 허용되지 않은 파라미터 필터링
- 각 도구에 누락된 파라미터 default 값 추가

```python
# executor.py - 파라미터 필터링
allowed_params = {p.name for p in tool._get_parameters()}
filtered_input = {k: v for k, v in action.input.items() if k in allowed_params}
ignored_params = set(action.input.keys()) - allowed_params
if ignored_params:
    logger.warning(f"Ignoring unexpected parameters: {ignored_params}")
```

## 근본 원인 분석

### 왜 도구 파라미터 오류가 반복되는가?

**현재 문제**:
```python
# registry.py - 현재 구현
def get_descriptions_for_llm(self) -> str:
    # 텍스트 설명만 제공, JSON Schema 형태 아님
    tool_descriptions.append(definition.to_llm_description())
```

```python
# base.py - to_llm_description()
def to_llm_description(self) -> str:
    return f"""**{self.name}** [{self.cost} cost]
  {self.description}
  Parameters:
    - query (str, required): 검색 쿼리
"""
```

**문제점**:
1. LLM에게 파라미터 정보가 자연어 텍스트로만 전달됨
2. LLM이 이를 무시하거나 잘못 해석할 수 있음
3. 파라미터 타입, 필수 여부 등이 강제되지 않음
4. 매번 새로운 도구에서 같은 문제 반복

## 권장 해결 방안: OpenAI Function Calling

### 왜 Function Calling인가?

| 항목 | 현재 방식 (Prompt 기반) | Function Calling |
|------|-------------------------|------------------|
| 파라미터 전달 | 자연어 텍스트 | JSON Schema |
| 타입 검증 | 없음 | OpenAI가 자동 검증 |
| 필수값 검증 | 없음 | OpenAI가 자동 검증 |
| 에러 발생 | 런타임에 발견 | 호출 전 차단 |
| 유지보수 | 도구마다 수동 수정 필요 | 스키마 정의만 하면 됨 |

### 구현 방향

```python
# 도구를 OpenAI Function 형식으로 변환
def to_openai_function(self) -> dict:
    return {
        "type": "function",
        "function": {
            "name": self.name,
            "description": self.description,
            "parameters": {
                "type": "object",
                "properties": {
                    p.name: {
                        "type": self._python_type_to_json(p.type),
                        "description": p.description,
                    }
                    for p in self.parameters
                },
                "required": [p.name for p in self.parameters if p.required],
            },
        },
    }
```

```python
# Reasoner에서 Function Calling 사용
response = await self.llm.ainvoke(
    prompt,
    tools=self.tools.get_openai_functions(),
)

# tool_calls에서 액션 파싱 (자동 검증됨)
if response.tool_calls:
    tool_call = response.tool_calls[0]
    action = Action(
        name=tool_call["name"],
        input=tool_call["arguments"],  # 이미 검증된 파라미터
    )
```

## 구현 완료: OpenAI Function Calling

### 변경된 파일들

#### 1. `backend/app/services/agent/study_plan/v4/tools/base.py`
- `ToolDefinition.to_openai_function()` 메서드 추가
- `_python_type_to_json_schema()` 헬퍼 메서드 추가
- Python 타입을 JSON Schema 타입으로 변환

```python
def to_openai_function(self) -> dict:
    """Convert tool definition to OpenAI Function Calling format."""
    properties = {}
    required = []

    for p in self.parameters:
        prop_schema = self._python_type_to_json_schema(p.type)
        prop_schema["description"] = p.description
        if p.default is not None:
            prop_schema["default"] = p.default
        properties[p.name] = prop_schema
        if p.required:
            required.append(p.name)

    return {
        "type": "function",
        "function": {
            "name": self.name,
            "description": self.description,
            "parameters": {
                "type": "object",
                "properties": properties,
                "required": required,
            },
        },
    }
```

#### 2. `backend/app/services/agent/study_plan/v4/tools/registry.py`
- `get_openai_functions()` 메서드 추가
- FINISH 특수 함수 정의 포함
- `get_tool_names_for_prompt()` 헬퍼 메서드 추가

#### 3. `backend/app/services/agent/study_plan/v4/core/reasoner.py`
- `use_function_calling` 플래그 추가 (기본값: True)
- `_reason_with_function_calling()` 메서드 추가
- `_reason_with_prompt()` 메서드 (기존 로직, fallback)
- `reason()` 메서드가 Function Calling 우선 사용, 실패 시 fallback

#### 4. `backend/app/services/agent/study_plan/v4/prompts/reasoning.py`
- `FUNCTION_CALLING_SYSTEM_PROMPT` 추가
- `FUNCTION_CALLING_USER_PROMPT` 추가

### Function Calling 동작 방식

```
1. Reasoner.reason() 호출
   │
   ├── use_function_calling=True (기본값)
   │   └── _reason_with_function_calling()
   │       ├── SystemMessage + HumanMessage 구성
   │       ├── get_openai_functions()로 도구 스키마 가져오기
   │       ├── llm.ainvoke(messages, tools=functions)
   │       ├── response.tool_calls에서 액션 추출
   │       └── 성공 시 Action 반환, 실패 시 fallback
   │
   └── fallback or use_function_calling=False
       └── _reason_with_prompt() (기존 방식)
```

### 기대 효과

1. **파라미터 오류 감소**: OpenAI가 JSON Schema 기반으로 자동 검증
2. **필수 파라미터 보장**: `required` 필드로 누락 방지
3. **타입 안전성**: JSON Schema 타입으로 변환되어 전달
4. **유지보수 용이**: 도구에 `_get_parameters()` 정의하면 자동 적용
