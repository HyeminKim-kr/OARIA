# Auth 스키마 구현 (Backend)

> **Category**: backend
> **Date**: 2025-12-31
> **Status**: completed

---

## Context (배경/근거)

### 이전 작업
- `database-01-251231.md`에서 Auth 스키마 설계 완료
- 5개 테이블 설계: `users`, `social_accounts`, `user_refresh_tokens`, `admin_users`, `admin_refresh_tokens`

### 현재 문제
- 기존 `users` 테이블에 `google_id`, `is_superuser` 컬럼이 직접 있음
- JWT refresh token 관리 체계 없음
- 소셜 로그인 확장 불가

### 목표
- 설계된 스키마를 실제 코드로 구현
- Backend (FastAPI) 먼저 진행
- Admin Backend (NestJS)는 별도 작업으로 진행

---

## Solution (해결 방안)

### 접근 방식
1. Alembic 마이그레이션으로 스키마 변경
2. SQLAlchemy 모델 추가/수정
3. 서비스 및 라우터 로직 수정

### 작업 항목

#### Phase 1: 스키마 마이그레이션
- [x] `social_accounts` 테이블 생성

- [x] `users`에서 `google_id`, `is_superuser` 컬럼 제거
- [x] `user_refresh_tokens` 테이블 생성

#### Phase 2: 모델 수정
- [x] `app/models/user.py` 수정 (google_id, is_superuser 제거)

- [x] `app/models/refresh_token.py` 생성
- [x] `app/models/__init__.py` 업데이트

#### Phase 3: 서비스/라우터 수정
- [x] `user_service.py` 수정 (소셜 계정 조회 로직)
- [x] `token_service.py` 생성 (refresh token 관리)
