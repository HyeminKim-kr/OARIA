### 아키텍처 요약

```
13개 노드 + 3개 조건부 루프

Loop 0 (가설 명확화):
  parse_hypothesis → [clarification_needed?] → clarify → parse (재시도)

Loop 1 (검색 확장):
  search_studies → [coverage < 0.6?] → expand → search (재시도, max 2회)

Loop 2 (Critic 수정):
  design_experiments → critique → [quality < 0.8?] → design (재시도, max 2회)

승인 게이트:
  approval_gate → [needs_user?] → END (선택지 제공) 또는 synthesize
```

## Bug Fixes

### 1. Dataclass 필드 순서 오류
- **에러**: `TypeError: non-default argument 'resource_feasibility' follows default argument`
- **원인**: `FeasibilityAssessment` dataclass에서 기본값 없는 필드가 기본값 있는 필드 뒤에 위치
- **수정**: `state.py`의 `FeasibilityAssessment` 필드 순서 재정렬

### 2. LangGraph 무한 루프 오류
- **에러**: `Recursion limit of 25/50 reached without hitting a stop condition`
- **원인**: Loop 0 (가설 명확화)에서 무한 루프
  - `clarify_hypothesis`에서 `clarification_needed = False` 설정했지만
  - `parse_hypothesis`가 다시 confidence 기반으로 `clarification_needed = True` 설정
- **수정**:
  - `clarify_hypothesis.py`: `clarification_needed = False` 설정 추가
  - `parse_hypothesis.py`: `clarification_count > 0`이면 무조건 `clarification_needed = False`
  - `service.py`: `recursion_limit: 50` 설정 추가 (ainvoke, astream 모두)

### 3. OpenAI API Key 속성명 오류
- **에러**: `'Settings' object has no attribute 'OPENAI_API_KEY'`
- **원인**: config.py의 설정명은 `openai_api_key` (소문자)인데, 노드들이 `OPENAI_API_KEY` (대문자)로 접근
- **수정**: 12개 노드 파일 모두 `settings.OPENAI_API_KEY` → `settings.openai_api_key`로 변경
