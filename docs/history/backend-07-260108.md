# RAG 전략 DB 동기화 시스템 구축

> **Category**: backend
> **Date**: 2026-01-08
> **Status**: completed

---

## Context (배경)

### 문제점

이전 batch-09-260108 작업에서 Batch RAG 모듈을 구축했지만, 전략 정보 관리에 문제가 있었음:

1. **코드 중복**: Backend와 Batch 모두 chunker/embedder 정의를 가지고 있음
2. **동기화 문제**: Backend는 정보 표시용, Batch는 실제 실행용으로 분리되어 있지만 일관성 유지 어려움
3. **전략 목록 관리**: Admin UI에서 사용 가능한 전략 목록을 어디서 가져올지 불명확

### 해결 방향

- Backend에서 "정적 정보"만 정의 (이름, 설명, 설정값)
- 서버 시작 시 코드에서 DB로 자동 동기화 (NestJS init 패턴)
- Admin UI는 DB에서 전략 목록 조회
- Batch는 실제 구현체만 보유

---

## Solution (해결 방안)

### 아키텍처

```
┌─────────────────────────────────────────────────────────────────┐
│ 서버 시작 시                                                     │
│                                                                  │
│   Backend 코드          →  sync_rag_strategies()  →  DB         │
│   ├── retrievers (registry)                        rag_strategies│
│   ├── rerankers (registry)                         테이블        │
│   └── batch_strategies.py (정적 정의)                            │
│       ├── chunkers                                              │
│       └── embedders                                             │
│                                                                  │
│ 런타임                                                           │
│                                                                  │
│   Admin UI  →  GET /lab/strategies/db  →  rag_strategies 조회   │
│                                                                  │
│   Batch     →  실제 chunker/embedder 구현체 사용                 │
└─────────────────────────────────────────────────────────────────┘
```

## DB 스키마

### rag_strategies 테이블

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID | PK |
| category | VARCHAR(50) | chunker, embedder, retriever, reranker |
| name | VARCHAR(100) | 전략 이름 |
| description | TEXT | 설명 |
| config | JSONB | 기본 설정값 |
| location | VARCHAR(20) | backend 또는 batch |
| is_active | BOOLEAN | 활성 여부 |
| created_at | TIMESTAMPTZ | 생성 시각 |
| updated_at | TIMESTAMPTZ | 수정 시각 |

- UNIQUE: (category, name)
- 인덱스: category, is_active

## Notes

- 기존 `/lab/strategies` 엔드포인트는 하위 호환성을 위해 유지
- Admin에서는 새 `/lab/strategies/db` 엔드포인트 사용 권장
- 코드에서 제거된 전략은 DB에서 `is_active=false`로 비활성화됨
- 마이그레이션 실행 필요: `uv run alembic upgrade head`
