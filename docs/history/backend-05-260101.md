## Context (배경)

- 원인 분석 필요

## 문제 분석

### 근본 원인
1. **FastAPI StreamingResponse 버퍼링**: 일정량의 데이터가 쌓일 때까지 실제 전송 지연
2. **동기 함수들의 이벤트 루프 블록**:
   - `rag_service.retrieve()` - 동기 함수 (embedding API + Weaviate 쿼리)
   - `llm_service.generate_stream()` - 동기 제너레이터 (mock의 `time.sleep()` 포함)
3. **`asyncio.to_thread()` 사용해도 SSE 버퍼링 문제는 해결 안 됨**

### 해결 방안
- `sse-starlette` 라이브러리 도입
- `EventSourceResponse` 사용 시 각 이벤트가 즉시 flush됨
- LLM 스트리밍을 별도 스레드 + 큐 패턴으로 변경

  - LLM 스트리밍: 별도 스레드 + 큐 패턴

## Notes

- `EventSourceResponse`는 각 yield 시 즉시 클라이언트로 전송
- 동기 제너레이터(LLM)를 비동기로 처리하기 위해 스레드 + 큐 사용
- RAG 검색은 `asyncio.to_thread()`로 별도 스레드에서 실행
