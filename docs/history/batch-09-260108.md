## Context (배경)

### 현재 아키텍처 분석

#### 1. User Backend RAG 모듈 (`backend/app/rag/`)

```
backend/app/rag/
├── registry.py         # Strategy Registry (데코레이터 기반)
├── base.py             # 공통 타입 (Chunk, SearchResult 등)
├── chunkers/           # 청킹 전략
│   ├── fixed_size.py   # FixedChar1000Chunker (name="fixed_char_1000_200")
│   └── semantic.py     # SemanticChunker
├── embedders/          # 임베딩 모델
│   └── openai.py       # OpenAI3SmallEmbedder (name="openai_3small_1536d")
├── retrievers/         # 검색 전략 (검색 시점 사용)
│   └── hybrid.py       # HybridRetriever
└── rerankers/          # 리랭킹 모델 (검색 시점 사용)
    ├── bge.py          # BGEReranker
    └── none.py         # NoReranker
```

- **역할**: Admin Lab UI에서 전략 목록 제공, 검색/리랭킹 실행
- **특징**: `@register_*` 데코레이터로 자동 등록, docstring이 UI 설명으로 표시

#### 2. Batch 모듈 (`batch/src/`)

```
batch/src/
├── chunker/
│   └── chunker.py      # TextChunker (단일 클래스, 설정값만 변경)
├── embedding/
│   └── embeddings.py   # EmbeddingClient (OpenAI만 지원)
└── tasks/
    ├── embed.py        # 프로덕션 임베딩 태스크
    └── sample_embed.py # 샘플 임베딩 태스크 (문제 발생 지점)
```

- **역할**: 실제 논문 청킹/임베딩 실행 (Celery 워커)
- **문제점**: 자체 구현체 사용, Backend registry와 연동 안 됨

#### 3. Admin 모듈

```
Admin Frontend → Admin Backend (NestJS) → User Backend (FastAPI)
                      ↓
              GET /lab/strategies/detail
                      ↓
              Backend registry에서 전략 목록 반환
                      ↓
              Admin UI 드롭다운에 표시
```

- **Lab 페이지**: 검색/답변 생성 테스트 (User Backend 직접 사용)
- **Embedding 관리 페이지**: 샘플 임베딩 생성 (Batch/Celery 사용)

### 문제점

1. **이름 불일치**
   ```
   Admin UI 선택값 (Backend registry)    Batch sample_embed.py 지원값
   ───────────────────────────────────   ────────────────────────────
   fixed_char_1000_200                   "semantic", "fixed", "large" (불일치!)
   openai_3small_1536d                   "openai", "openai-large" (불일치!)
   ```

2. **역할 혼재**
   - Backend RAG: 검색 시점 전략 + 인덱싱 시점 전략 모두 정의
   - 실제 인덱싱은 Batch가 하지만 전략은 Backend에서 정의
   - 코드 중복 및 동기화 문제

3. **Celery 트리거 실패**
   - User Backend에 `celery` 패키지 없음
   - 샘플 임베딩이 pending 상태로 유지됨

### 올바른 역할 분리

```
검색 시점 (User Backend)              인덱싱 시점 (Batch)
────────────────────────              ────────────────────────
사용 시점: 쿼리 요청 시                사용 시점: 논문 수집/임베딩 시

필요한 전략:                          필요한 전략:
├── Retrievers (검색)                 ├── Chunkers (청킹)
├── Rerankers (리랭킹)                └── Embedders (임베딩)
└── (Classifiers, Evaluators)

실행 환경: FastAPI (동기/비동기)      실행 환경: Celery Worker (비동기)
```

## Solution (해결 방안)

### 설계 방향

1. **Batch에 RAG 모듈 시스템 구축** - Backend와 동일한 패턴 사용
2. **전략 이름 동기화** - 동일한 이름 사용으로 혼란 방지
3. **Admin UI 전략 목록** - 인덱싱 전략은 Batch에서 조회

### 아키텍처 변경

```
변경 전:
┌─────────────────────────────────────────────────────────────────┐
│ Admin Frontend                                                   │
│     ↓ GET /lab/strategies                                       │
│ Admin Backend → User Backend → registry.py                      │

│ Admin Backend → User Backend → Celery → ???                     │

변경 후:
```

## Notes

- Backend의 chunker/embedder는 참조용으로만 유지 (향후 제거 가능)
- Batch RAG가 인덱싱의 "source of truth"
- 검색 시점 전략 (retriever, reranker)은 Backend RAG 유지
- 전략 이름은 반드시 동기화하여 Admin UI 혼란 방지
