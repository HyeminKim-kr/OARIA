# 논문 채팅봇 프롬프트, UI 개선 및 고급 기능

> **Category**: backend, frontend
> **Date**: 2026-01-19
> **Status**: completed

## Context (배경)

- 논문 상세 페이지 채팅봇이 기존 멀티 논문 RAG와 동일한 프롬프트 사용
- "여러 논문 비교", "[1], [2] 인용" 등 단일 논문 맥락에 맞지 않는 지시 포함
- UI에서 "References"가 다른 논문 참조처럼 보이지만 실제로는 같은 논문의 섹션
- Reranker 모델(567M) CPU 로딩 시간이 6분 이상 소요

## Solution (해결 방안)

### 1. Reranker 비활성화 (임시)
- [x] `backend/.env.docker`에 `RERANKER_ENABLED=false` 추가
- CPU 환경에서 로딩 시간 문제 해결

### 2. 논문 전용 대화형 프롬프트 추가
- [x] `PAPER_CHAT_PROMPT` 상수 정의
- [x] 단일 논문 맥락에 맞는 대화형 스타일
- [x] 마크다운 헤더 금지, 자연스러운 문장 사용
- [x] "이 논문에서는", "Methods 부분을 보면" 등 표현 사용
- [x] llm_service에 커스텀 프롬프트 파라미터 추가

### 3. 프론트엔드 UI 개선
- [x] "References" → "근거 섹션" 변경
- [x] 참조 표시를 칩(pill) 형태로 변경 (섹션명만 강조)
- [x] 같은 논문 내 참조임을 명확히 표시

- "이 논문에서는", "Methods 부분을 보면" 등 표현 사용

## Notes

- Reranker 비활성화는 임시 해결책
- 향후 질문 유형별 라우팅 고려:
  - 요약 질문 → Reranker 불필요, 캐시 사용
  - 구체적 QA → Retrieval + Reranker
  - 근거 요청 → Retrieval + Reranker + offset
- 근거 섹션 클릭 시 해당 위치로 스크롤 기능 추가 검토

## 추가 기능: 질문 라우팅 + 하이라이트

### 1. 질문 유형별 스마트 라우팅

**파일**: `backend/app/services/question_classifier_service.py` (신규)

LLM 기반 질문 분류기:
- `summary`: 요약/핵심 질문 → Reranker 없이, abstract/conclusion에서만 검색
- `qa`: 구체적 QA → Retrieval + Reranker
- `evidence`: 근거 요청 → Retrieval + Reranker + 높은 임계값

**파일**: `backend/app/routers/paper_chat.py`

- 질문 분류 후 전략 적용
- classification SSE 이벤트 추가
- 전략별 RAG 파라미터 적용 (use_reranker, sections, min_score)

### 2. 논문 본문 하이라이트

**파일**: `frontend/src/app/papers/[id]/page.tsx`

- `highlightInfo` 상태 추가
- 섹션 ref 등록 및 자동 스크롤
- 노란색 하이라이트 스타일 (5초 후 자동 해제)

**파일**: `frontend/src/components/paper-chat/PaperChatPanel.tsx`

- `onHighlightRequest` 콜백 prop 추가
- 근거 섹션 클릭 시 부모에 하이라이트 요청
