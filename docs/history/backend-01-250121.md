### 설계 문서 주요 내용 (v2.1 최종)

1. **아키텍처**: 12개 노드 + 3개 루프
   - parse_hypothesis (가설 구조화 + 동의어 확장)
   - clarify_hypothesis (명확화 요청) [Loop 0]
   - decompose_to_test_questions (Necessity/Sufficiency/Epistasis/Specificity + decision_rule)
   - search_prior_studies (유사 연구 RAG 검색)
   - **expand_search** ★ NEW [Loop 1: 검색 커버리지]
   - **build_evidence_pack** ★ NEW (별도 노드로 분리)
   - analyze_methodologies (방법론 분석)
   - design_experiments (실험 설계)
   - critique_and_refine [Loop 2: Critic 수정]
   - identify_measurements (측정치 도출)
   - validate_feasibility (실현 가능성)
   - **approval_gate** ★ NEW (별도 노드, choices 제공)
   - synthesize_plan (최종 계획서 생성)

2. **핵심 데이터 구조**:
   - `TestQuestion` (category + **decision_rule**)
   - `EvidenceSnippet` (paper_id, section, offset, claim_type, text)
   - `EvidencePack` (논문별 Evidence 묶음)
   - `CritiqueReport` (**5종 대조군** 포함)
   - `RevisionRecord` (**수정 이력**)
   - `ApprovalChoice` (**선택지** 제공)

3. **3개 조건부 루프**:
   - Loop 0: 가설 불명확 → clarify → 재파싱
   - Loop 1: coverage < 0.6 → expand_search (max 2회)
   - Loop 2: quality < 0.8 → redesign (max 2회)

4. **승인 게이트 개선**:
   - `approval_items`: 승인 필요 항목 목록
   - `choices`: 사용자 선택지 제공 (전체승인/범위축소/대안)
   - `approval_log`: 승인 요청/응답 기록

5. **버전 비교표**:
   | 항목 | v1.0 | v2.0 | v2.1 |
   |------|------|------|------|
   | 노드 수 | 7 | 9 | **12** |
   | 검색 루프 | ❌ | ❌ | ✅ |
   | Evidence Pack | ❌ | 내부 | ✅ 별도 |
   | decision_rule | ❌ | expected | ✅ |
   | Critic 대조군 | 4종 | 4종 | **5종** |
   | revision_history | ❌ | ❌ | ✅ |
   | approval choices | ❌ | 기본 | ✅ |

## Notes

- 주도성 = **반복 루프 + 판단 게이트 + 자기검증**
- 검증 질문 분해가 실험 설계의 "골격"이 됨
- Evidence Pack으로 "왜 이 결과가 이렇게 나왔지?" 추적 가능
- 승인 게이트로 비용/윤리 큰 단계 사용자 **선택** 가능
- revision_history로 무엇을 왜 바꿨는지 기록
