## Context (배경)

### 문제 발견

Reference 모달에서 하이라이트가 정확하지 않은 현상 발생:

1. **Weaviate 오프셋**: fulltext 기준 (예: 1948-4741)
2. **XML 파서 오프셋**: 섹션 기준 (예: 0-4206)
3. **프론트엔드**: fulltext 오프셋으로 섹션 텍스트에 하이라이트 시도 → 불일치

### 임시 해결 (frontend-03-260101)

- `section_fulltext_offset` 필드 추가로 오프셋 변환
- 그러나 근본적인 문제가 남아있음

### 근본 원인: 두 개의 XML 파서

| 파서 | 위치 | 용도 | 로직 |
|------|------|------|------|
| **Batch Parser** | `batch/src/parsers/xml_parser.py` | 임베딩/Weaviate 저장 | 모든 자식 요소를 공백으로 연결 |
| **Backend Parser** | `backend/app/services/xml_section_parser.py` | 모달 디스플레이 | `<p>` 태그만 명시적 처리 |

**핵심 차이 (Line 288-292 vs 170-176)**:

```python
# Batch Parser - 모든 자식 요소 추출
for child in sec:
    if child.tag != "title":
        sec_text_parts.append(extract_text_from_element(child))
sec_text = " ".join(sec_text_parts)  # → 8,880자

# Backend Parser - <p> 태그만 추출
for child in sec:
    if child.tag == "p":
        text = clean_text(extract_text_from_element(child))
        paragraphs.append(...)  # → 6,330자
```

**결과**: 같은 Introduction 섹션인데 텍스트 길이가 다름 (8,880자 vs 6,330자)

## Solution (Two-Layer 아키텍처)

### 개념

```
┌─────────────────────────────────────────────────────────────┐
│                    Two-Layer Architecture                    │
└─────────────────────────────────────────────────────────────┘

1. Index Text Layer (오프셋 기준)
   ├── 정규화된 plain text
   ├── 공백/줄바꿈 규칙 고정
   ├── 오프셋 저장 기준 (Weaviate)
   └── 하이라이트 좌표 기준

2. Display Model Layer (가독성용)
   ├── XML 구조 보존 (섹션/문단)
   ├── 가독성 있는 렌더링
   └── 하이라이트는 문단 내부에서 적용
```

### 데이터 흐름

```
XML 원본
    │
    ▼
┌─────────────────┐
│  Batch Parser   │
│ (Index Layer)   │
├─────────────────┤
│ 1. 모든 텍스트 추출
│ 2. 정규화 (공백 통일)
│ 3. fulltext 생성
│ 4. 오프셋 계산
│ 5. Weaviate 저장
└────────┬────────┘
         │
         ▼
    Weaviate DB
    (fulltext 기준 오프셋)
         │
         ▼
┌─────────────────┐
│ Backend Parser  │
│ (Display Layer) │
├─────────────────┤
│ 1. XML에서 구조 추출
│ 2. 문단별 분리
│ 3. 각 문단의 fulltext 오프셋 계산
│ 4. 프론트엔드로 전달
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   Frontend      │
├─────────────────┤
│ 1. 문단별 렌더링
│ 2. 하이라이트 오프셋을 문단 내부 좌표로 변환
│ 3. <mark> 태그로 하이라이트
└─────────────────┘
```

### 핵심 원칙

1. **Index Text는 Source of Truth**: Weaviate에 저장된 fulltext가 오프셋의 기준
2. **Display는 Index Text와 동기화**: Display 파서도 Index Text와 동일한 텍스트를 생성해야 함
3. **문단별 오프셋 매핑**: 각 문단이 fulltext에서 어디에 있는지 알아야 함

## 작업 항목

### Phase 1: 파서 통합 (필수)

#### 접근 방법: Backend Parser 수정

현재 문제:
```python
# Backend Parser (현재) - <p> 태그만 처리
for child in sec:
    if child.tag == "p":
        paragraphs.append(...)
```

수정 방향:
```python
# Backend Parser (수정) - 모든 자식 요소 처리 (Batch Parser와 동일)
for child in sec:
    if child.tag == "title":
        continue
    text = clean_text(extract_text_from_element(child))
    if text:
        paragraphs.append(Paragraph(
            text=text,
            offset_start=current_offset,
            offset_end=current_offset + len(text),
        ))
        current_offset += len(text) + 1  # +1 for space (Batch Parser는 공백으로 연결)
```

#### 핵심 변경

1. **모든 자식 요소 처리**: `<p>` 뿐만 아니라 `<table-wrap>`, `<list>`, `<fig>` 등 모든 요소
2. **오프셋 계산**: Batch Parser의 `" ".join()` 로직과 일치하도록 공백(+1) 포함
3. **문단 = 자식 요소**: 각 자식 요소를 하나의 문단으로 취급

- [ ] Backend Parser 수정: 모든 자식 요소 추출
- [ ] 오프셋 계산 로직 Batch Parser와 동기화
- [ ] 테스트: 같은 XML → 같은 텍스트 길이 확인

### Phase 2: 오프셋 매핑 개선

- [ ] API 응답에 문단별 fulltext 오프셋 포함

## Notes

### 고려사항

1. **기존 데이터 호환성**: 이미 Weaviate에 저장된 오프셋은 Batch Parser 기준
2. **Backfill 필요 여부**: 파서 변경 시 재임베딩 필요할 수 있음
3. **성능**: Display 파싱은 API 요청마다 수행됨

### 대안 (검토 후 기각)

- ❌ fulltext.txt 제거: Weaviate가 fulltext 기준 오프셋을 사용하므로 불가
- ❌ Weaviate 스키마 변경: 기존 데이터 마이그레이션 비용 큼
